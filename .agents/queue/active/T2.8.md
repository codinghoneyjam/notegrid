## Notes

Three defects made g10 fail on all three engines, all silent (the page only ever saw
a bare `onprocessorerror`, so every engine looked identical: a quiet node):

1. **`NgEngineProcessor` did not extend `AudioWorkletProcessor`.** A registered class
   without that base is rejected by the audio thread. The existing comment claimed the
   name could not be written because the file is type-checked on the main thread; that is
   true of `tsc`, and the fix reads the base off `globalThis` at run time instead.

2. **The port was read from `globalThis`.** `AudioWorkletGlobalScope` does not expose it
   as a global, so `globalThis.port` is `undefined` and the message handler never bound.
   Found by adding one member at a time to a class known to work:

       this.port.onmessage     -> works
       this.host = this        -> works
       this.host = globalThis  -> processorerror, no message

3. **`Ng`'s `TextDecoder` was a class field**, so it threw at construction inside the
   worklet. D05 and SP-1 both record that the realm lacks it; the engine path never
   decodes UTF-8, so the decoder is now built on first use and raises a named
   `E_NO_TEXT_DECODER` rather than a `ReferenceError`.

A fourth defect was in the spec itself: `placeNote(0, ...)` added a note to lane index 0,
but `note.lane` is a lane *id* (I-01: ids unique and >= 1; schema `minimum: 1`), and
C2.8 keeps the array index as the separate `slot` concept. The engine correctly answered
`E_LANE_MISSING at /notes/3/0`, which compiles to silence rather than a visible failure.

`worklet.js` is now gitignored alongside `harness.js`; both are build outputs.
